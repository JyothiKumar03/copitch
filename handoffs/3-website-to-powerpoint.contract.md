# Contract: Website to PowerPoint (module 3)

Owner decisions pending: The owner will deploy to AWS after accepting the local result. Run the deployed smoke against the owner’s release target when available.

Source: Owner request for website-to-PowerPoint, the private project entry at `/research`, and `docs/orchestration.md`.

| ID | Actor action | Observable outcome | Check (entry point + exact command or click path) | Required evidence |
|----|--------------|--------------------|---------------------------------------------------|-------------------|
| AC-1 | Signed-in host adds a public website to a private project | The host can set the starting URL, audience, presentation goal and crawl depth and review them before starting. Approval starts one durable capture job tied to the project and approved inputs. | At `/research`, sign in, open a project, choose its website walkthrough action, enter the fixture origin and goal, and review the capture scope. Verify no capture occurs before approval. Approve twice and confirm a single durable job and an unchanged saved input snapshot. | fixture |
| AC-2 | Host approves exploration of a public site | A bounded Playwright browser opens the approved origin and follows eligible, visible same-origin navigation. It saves which pages were actually seen, their URLs and screenshots. External destinations, writes, sign-in prompts and page-directed instructions cannot extend the worker’s authority. | Use a controlled public fixture with a home page, two internal links, an off-site link, a form and a broken page. From the `/research` website workflow approve the site and compare observed page requests, screenshots, link scope and completed/failed activity to the fixture. | fixture |
| AC-3 | Host downloads PowerPoint from a completed walkthrough | The persisted `.pptx` opens as a real PowerPoint deck. Slides follow the specified audience and goal. Facts, screenshots and clickable links correspond to visited pages. Pages whose content was unavailable are identified as gaps without fabricated images or findings. | Open the walkthrough result in the saved project, inspect the actual page records, download the `.pptx` and open it in PowerPoint or LibreOffice. Compare slide images and links against captured URLs and include a fixture failure. Check legibility on a projected-size frame. | fixture |
| AC-4 | Host closes the browser during capture and later reopens the project | The job remains recoverable and the finished result retains its approved inputs, ordered page records and same downloadable revision. Another account cannot read its job, screenshots or deck. | Start capture from `/research`, duplicate the request and close the browser while the job is active. Sign in from a clean browser and compare the result and PowerPoint revision. Repeat the result and download requests signed in as a different account and observe denial. | fixture |
| AC-5 | Host submits an invalid, internal or inaccessible website | The host sees an actionable rejection or failure without an unsafe navigation or a blank success. The previous saved walkthrough remains available for recovery. | At `/research`, try localhost, a private destination, an invalid URL, and a public fixture route that redirects outside the allowed scope. Verify that the request or redirected load is blocked before capture, and retry with the approved reachable site. | fixture |
| AC-6 | Host runs the full workflow on the AWS deployment | The deployed HTTPS studio signs the host into a private project, runs the public walkthrough, renders progress and returns a valid PowerPoint that survives a new sign-in. | Open the deployed `/research`, use an approved public test site and repeat AC-1, AC-3 and AC-4. Record URL, release version, health/readiness status, capture outcome and PowerPoint reopen evidence. | deployed |
| AC-7 | Host limits how far the walkthrough can follow links | Crawl depth accepts whole numbers from 0 through 3 and defaults to 2. The starting page has depth 0. The approved depth is saved with the job, independent of the maximum page count, and no target beyond the approved link distance is requested. | In the website walkthrough action at `/research`, review the default depth, then submit a fixture site with linked descendants at depths 0, 1, 2 and 3. Verify that the default reaches depth 2 and the transport never requests depth 3. Repeat at 0 and 3. Confirm stored depth on each captured page and reject `4`. | fixture |

Out of scope: Signing in to third-party sites, submitting site forms, cross-origin navigation, and modifying the approved website.

Invariants: Explicit approval, project isolation, exact capture provenance, read-only bounded exploration, private screenshots and decks, and durable job and revision identity.
