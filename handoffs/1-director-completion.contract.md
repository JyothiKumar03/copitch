# Contract: Director-led pitch delivery (module 1)

Owner decisions pending: Keep public release, AWS provisioning and deployment, provider retention for sensitive inputs, access to the owner's named project, reuse of signed-in screenshots in audience artifacts, and access to a real physical microphone with the owner. Confirm the configured Director and browser model IDs and image-input support before live rehearsals. The documented default budgets are USD 2.00 per mission and per site run, metered separately. Raising either cap or enabling chargeable actions on a real site requires owner approval. A4 requires an owner-approved disposable app, test account and dataset. Confirm the manual slide-count default (6 in the completion plan, 5 in the UI spec) and the release layout threshold (55% content fill in the completion plan, 70% in the UI spec). Report both timing measures in A6 because server-event latency and physical onset latency start at different points.
Source: `docs/completion-plan.md` §§1–12, `docs/ui-ux-spec.md`, `docs/release-checklist.md`, `docs/orchestration.md`, and the signed-in `/research?project=<id>` conversation, website, preview and live paths. The Director belongs to Module 1 and delegates to the existing Module 2 presentation and Module 3 walkthrough workflows.

A signed-in host tells the studio what they need to present, approves the outcome and source scope, and receives a cited deck they can rehearse, revise, present or reopen. A website task can supply steps to that deck. If the requested deck cannot be verified, the studio explains what is missing and gives the host a way to proceed.
