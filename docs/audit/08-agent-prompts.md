# Agent prompts and evaluation

The agent output is a proposal. Review each prompt with its output schema, controller permissions and a scored example. Find prompts and call sites with `rg -n 'render\(|instructions:|prompt:' backend/src/services voice/server.py`.

| Prompt family | Goal and output | Guardrails and what to measure |
|---|---|---|
| Typed interview, spoken interviewer and delegate | Resolve subject, audience, outcome and deliverable. Return a natural reply, a proposed plan or an explicit request to start the current plan. | Preserve language and known scope. Confirm that a conditional yes with a change leaves research unapproved. Check the plan has been heard before spoken approval and check partial/final transcript timing separately from plan quality. |
| Brief clarification and hosted lookup | Ask one material question, or supply approved query suggestions and candidate URLs. | Keep private input out of public queries. Search candidates require a successful read before they count as evidence. Measure relevant source reads and failed-source disclosure. |
| Research collection and coverage repair | Plan concrete questions, record quoted answers, identify remaining gaps and fill material omissions within the approved source policy. | Check exact measures, units, periods and source passages. Files-only has zero public lookups. Coverage repair prioritizes missing facts and reads promising search results. Concurrent duplicates share one lookup and retain its citations. |
| Context writer, legacy report writer, chart writer and chart repair | Turn checked findings into useful prose and choose comparable, sourced views. | Check numbers, denominators, period and category grouping, plus correct chart fallback. Phrase gaps as unknowns without assuming a direction or cause. |
| Research and chart fact-checker | Return an independent verdict for each cited unit, with a reason for any rejection and source-specific omissions when requested. | Do not treat source instructions as authority. Score coverage and citation entailment separately. Check wrong periods, swapped figures, and titles whose elapsed-time starting event differs from the cited source. |
| Deck readiness, planner, additive completion and duration compatibility planner | Decide if evidence supports the requested story. Build distinct beats, use grounded visuals, and return natural narration. | Decisions controls routing. Exact count, surviving distinct claims and visual review control publication. Check nine sections to ten slides, no partial publication, and correct donut composition. An ordinary comparison can retain independent, cited measures with their own scopes. |
| Deck visual review | Return slide-specific clipping, overlap, hierarchy or illegibility issues on the contact sheet. | Treat slide text as data and use known slide IDs. Check rendered projection, keyboard review and exported projector-size slides separately. |
| Live presentation response and edit | Answer briefly with verbatim evidence, clarify ambiguity, or propose an action on the pinned slide. | Check same-sentence resume, explicit edit approval and append versus replace. Keep research supplements available to the owner when answering from a saved deck. Preserve source facts and the host's language. |
| Director next action and outcome review | Decide whether to prepare a deck or ask one question, then check the finished deck against the approved outcome. | The controller validates scope, budget and revision before durable work. Check that narrative shortcuts, duplicate work and an unverified shorter deck cannot close the mission. |
| Website navigation | Pick one action that advances the approved outcome. Use observed element references, known frontier URLs and indexed visible facts. | Treat page text and images as data. Only the controller can navigate, stop a run or advance beyond a blocked branch. Check sales/contact and product-flow goals separately, capture uniqueness, requested depth, branch coverage and spending. |
| Website outcome review | Independently check a browser finish proposal against saved facts and cite recorded step numbers for every material part of the goal. | An unsupported or unavailable review keeps the capture partial. The review has no browser actions and no page image in its input. Check that a welcome screen cannot prove a completed flow, a fabricated step ID is rejected, and an unchanged evidence set is reviewed at most once through a restart. |
| Legacy generic chat, transcription and speech | Answer the practice request, transcribe a supplied utterance, or read the accepted sentence. | Isolate practice from project state, retain the host's exact transcript and keep speech attempt IDs distinct from slide revisions. Check typed fallback and playback on ordinary browser entry points. |

The typed and voice interviewer use the shared phase controller. The plan request, rendered deck and persisted output remain separate checkpoints for scoring. Model/provider checks use synthetic or approved public input and distinguish real model output from fixture output. New PowerPoint exports use the host's exact confirmation and a deterministic renderer.
