# Release review · The interruptible presenter

Review of the revised product, architecture and 12-hour plan against the current workspace. This is a proposed build board. The earlier direct-Realtime design and its simulation results describe a different voice path.

## What the demo must distinguish

Give two runs the same reviewed deck, approved setup URL, spoken instruction and partial-audio cutoff. In both, the host says “Show setup, only if it doesn't need login.” In one, the worker observes setup and the audience stage displays the matching frame. In the other, the worker encounters a login gate. “Continue” must produce different, defensible next sentences. A private fetch, successful synthesis, or plausible model answer is insufficient evidence that anything was displayed or delivered.

Use a three-point fixture. A has finished. B is partially delivered and its purpose is to explain setup. C is pricing. Define the actual requirement for B during planning:

| Approved requirement for B | Verified setup displayed | Blocked, aborted, stale or never painted |
|---|---|---|
| Either spoken explanation or successful setup demonstration satisfies B | On Continue, choose C. Record the visual objective as displayed and the narration attempt as partial. | Resume B at its safe sentence boundary. |
| Both the explanation and the demonstration are required | Explain the outstanding part of B, then select C. | Give the supported explanation if available and retain the blocked demo objective with Retry or Skip. |

If the final user instruction is “actually skip it,” discard the preparation. Resolve whether “it” refers to the proposed tour or the underlying point. A tour skip alone leaves a required spoken explanation due. This is the first fixture for both the controller builder and the independent test agent.

## Existing implementation and migration

- **Research is reusable.** The server already clarifies scope, enforces confirmation, validates source references, persists findings and downloads a cited memo. A supplied URL needs an actual completed page action plus a matching citation. Source matching establishes traceability. A reviewer or separate quality evaluation must check claim entailment. Keep the prose memo; store the generated execution plan as a sibling tied to the same evidence revision. Publish an approved bundle pointer atomically after validation.
- **Session storage is a starting point.** The generic run endpoint permits one active model run per session. The newer research endpoint has a separate path, awaits a build promise and deduplicates in process. The store constructor marks running generic jobs failed on open. Do not start a second process using that constructor. Keep Python and Chromium behind a single TypeScript writer, allow foreground commands during research, and use explicit leases/checkpoints for long jobs. Session-level events must span jobs, turns, presentation and playback. Persist a scoped host credential or reauthentication path so browser refresh can recover the session; the current research hook holds its session in a React ref.
- **Text-model support is reusable.** The shared SDK wrapper has ordered model entries and attempt costs; structured research calls use a separate path. Add distinct planner and live-router profiles, one explicit escalation path, actual serialized input budgets and usage by phase. Define a proposal-only router with Zod. Keep privileged execution behind controller validation. Instrument STT, TTS, search and wasted speculative work as separate cost categories.
- **Media and public stage are new work.** Replace the browser recognition/synthesis starter on the presentation path with authenticated SmallWebRTC microphone ingress to a Python Pipecat worker, a private voice event channel, and identified TTS assets played once in React. Deepgram and Cartesia are first-spike candidates. Keep Hono on Bun for the sprint, or separately migrate the current Bun-specific SQLite repository before selecting Node as the production runtime. Keep one host controlling the floor and a distinct audience view with narrowly scoped paint acknowledgments.
- **Deployment and instructions need reconciliation.** The Compose overlay covers Next.js, Hono, Caddy and persistence. Add supervised voice and isolated browser workers, media negotiation, venue-tested ICE/TURN, private asset delivery and worker authentication. HTTPS signaling success alone does not establish a working media path. Before delegating implementation, update root AGENTS.md, docs/architecture.md, docs/voice-architecture.md, docs/plan.md and docs/orchestration.md to select the cascade, exact clip playback and the 12-hour release gates. OpenAI-only voice and standalone Decisions are stale defaults for this build.

## Shared contract to freeze before parallel work

TypeScript owns commands, agenda, revisions and durable evidence. Python emits hypotheses, finalized segments and identified assets. The host player is the authority on application playout; the designated stage is the authority on the displayed frame. Neither establishes human perception. Use a language-neutral versioned wire schema with snake_case fields, T-prefixed TypeScript aliases and cross-language golden examples.

Include session ID, producer ID and incarnation, producer sequence, event ID, correlation ID, relevant attempt and expected revision. The controller assigns a durable commit sequence. Keep connection/playback generation independent of the research revision. On reconnect, reject old leases and outstanding attempts, load a paused snapshot and let the host resume. A repeated command returns the existing result. SQLite transactions are authoritative; derive the redacted JSONL judging trace from the committed events so a crash cannot create a second history.

Keep separate records for claims and their evidence; spoken attempts and cutoff uncertainty; demo objectives and verified frame acknowledgments; and agenda points with explicit completion requirements. A failed or unfinished event cannot silently satisfy a point. Model outputs can propose relevance changes. The controller uses the approved agenda, explicit skips, dependencies, pending choices and latest revision to select a continuation. When an earlier required point is blocked without an eligible fallback, offer retry, skip or clarification. Avoid spinning on it.

## Decisions and cut line

- Maintain the existing host's approval for content revisions. A new room choice grants authority only to select one of its offered routes. Distinguish a transient preview/filter from a saved deck edit. A stale “yes” cannot approve either.
- Treat agent-as-presenter as the judging path. Preserve the previously requested agent-as-audience role as a separate read-only listening/question policy. It is a secondary milestone unless required for the submission. An audience *device* and an audience *role* are separate.
- Pre-render one short asset per claim, with a cache key including approved text, voice, language and synthesis settings. Reuse unchanged assets across deck revisions only after rebinding them to the new approved attempt. Until calibrated word alignment exists, replay the partial claim at a natural boundary.
- Put the transport spike and held-out fixture design at kickoff, keep research as the first user-facing module, then build the full paired continuation demo before optional imports, additional layouts, PPTX styling or broader browsing. In the first 45 minutes use one fixture, one clip and one frame to expose the largest risk. Running every production component in that window is an unmeasured estimate.
- Give A and B the same raw playback, stage, permission and browser observations that C uses to derive state. Equalize tools, escalation accounting and evidence access. Freeze initial state and replay conditions. Score action **and** correct next point jointly, track false coverage separately, count unassisted and degraded runs separately. Record total cost per successful run and median latency; 16 held-out trials support a demo-sized comparison. If the frontier baseline ties or wins, report that result. Tune only on a disjoint development set; repeatedly fixing against held-out labels turns them into development data.
